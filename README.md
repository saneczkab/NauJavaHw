## Описание
Генератор паролей.
Проект в рамках курса "Промышленная разработка на Java" от Naumen.  

## Запуск
Приложение проверено на базе Java 21.
1) Соберите jar-файл: `mvn clean package -DskipTests`.
2) Запустите docker-контейнер: `docker-compose up --build`. Контейнер запустит PostgreSQL и само приложение.

## Технологии
- Java 21 + Maven
- Spring Boot
- Spring data JPA для работы с СУБД PostgreSQL
- Java Melody для мониторинга
- JUnit, Selenium для тестирования
- Docker для контейнеризации

## Архитектура
Паттерн MVC
- Model: модели и сервисы.
- View: Thymeleaf.
- Controller: View-контроллеры.

## Функции
Функции, отмеченные [ADMIN], доступны только пользователям с ролью ADMIN.
1) Регистрация: `http://localhost:8080/registration`, авторизация: `http://localhost:8080/login`.
2) Главная страница: `http://localhost:8080/`. Здесь пользователь может сгенерировать пароль.
3) Просмотр списка сгенерированных паролей: `http://localhost:8080/passwords`. Также есть возможность удалить пароль из списка.
4) [ADMIN] Просмотр списка всех пользователей: `http://localhost:8080/users/list`. Есть возможность удалить пользователя.
5) [ADMIN] Просмотр отчёта о работе сервиса: `http://localhost:8080/report`. Отчёт содержит информацию о количестве сгенерированных паролей и о числе зарегистрированных пользователей.
6) [ADMIN] JavaMelody: `http://localhost:8080/monitoring`.  

При запуске приложения создаётся пользователь с правами администратора: логин `admin`, пароль `admin`.

### О генерации паролей

Пользователь может выбрать, какие символы будут использоваться в пароле:
- Латинские буквы (заглавные и строчные): A-Z, a-z;
- Цифры: 0-9;
- Специальные символы: `` !@#$%^&*()_-+={[]};:'",<.>/?\|~` ``.  

Если ни один из вариантов не выбран, то по умолчанию используются только латинские буквы.  
Также пользователь может задать длину пароля и их количество.  
Если число задано некорректно, то используется значение по умолчанию - 12.

## Разделение ролей
1) Пользователь (Role.USER):
- Регистрация и вход.
- Генерация паролей заданной длины и заданного содержимого.
- Многопоточная генерация большого числа паролей.
- Просмотр истории генерации паролей.
- Удаление паролей из истории.
2) Администратор (Role.ADMIN):
- Удаление пользователей.
- Просмотр отчёта о работе сервиса.
- Доступ к системе мониторинга приложения.

## Безопасность
- Авторизация через Spring Security.
- Пароли от аккаунтов пользователей хранятся в виде хэшей. При авторизации сверяются именно хэши паролей.
- Сгенерированные пользователями пароли лежат на сервере в зашифрованном виде.
- Разделение ролей.
- Просматривать сгенерированные пароли может только их создатель. У любых других пользователей (даже у администраторов) такой возможности нет.
- crypto.secret-key в application.properties используется для шифрования сгенерированных паролей. Ключ в application.properties задан для примера. При разворачивании приложения следует сгенерировать новый.
